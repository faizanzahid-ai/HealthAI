# MASTER PROMPT — BUILD COMPLETE HEALTHCARE MOBILE APP PROTOTYPE

You are a senior **mobile app architect, Flutter/React Native developer, UI/UX designer, AI integration engineer, database engineer, and QA engineer**.

Build a **complete, polished, functional mobile app prototype** for an AI-assisted healthcare platform connecting:

* Patients
* Doctors
* Hospitals
* Blood donors

This is a **MOBILE-ONLY APPLICATION**.

Name of App is "Nexcure"
Do NOT build:

* Web application
* Desktop application
* Admin web dashboard
* Marketing website
* Landing page

The primary deliverable is a complete mobile application prototype that can be demonstrated on Android/iOS.

Use **Flutter + Dart** unless the existing environment requires React Native.

The application must use clean architecture and repository/service abstractions so a real backend can be connected later.

# 1. PRODUCT CONCEPT

The application is a healthcare platform for the Pakistani market.

Patients can:

* Search diseases or tumors
* Discover relevant doctors
* Discover nearby hospitals
* Filter results within 10–25 km
* View doctor profiles
* View hospital profiles
* Book appointments
* Chat with doctors
* Upload medical reports
* Receive AI-assisted report summaries in Urdu
* Share reports with doctors
* Receive follow-up reminders
* Scan handwritten prescriptions
* Extract medicine information
* View medicine price information
* View blood requests
* Follow hospitals
* Receive blood-request notifications
* Respond to blood requests

Doctors can:

* Manage their profile
* Manage appointment slots
* View appointments
* Communicate with patients
* View reports shared by patients
* View AI-generated report summaries
* Respond to patients
* Receive notifications
* Manage reviews

Hospitals can:

* Manage their hospital page
* Add/manage doctors
* Manage appointments
* Create social-style posts
* Create blood-request posts
* Have followers
* Notify followers about blood requests
* View donor responses
* Close/fulfill blood requests
* Manage hospital information

Blood donors can:

* Create donor profiles
* Set blood group
* Set availability
* Follow hospitals
* View followed-hospital posts
* Receive blood-request notifications
* View blood requests
* Respond that they can donate
* Track their responses

The application should feel like a serious, trustworthy healthcare product rather than a generic social-media application.

# 2. CORE PRODUCT PRINCIPLE

The application should behave as **one connected ecosystem**, not as separate prototype screens.

For example:

If a patient books an appointment:

```text
Patient
    ↓
Appointment created
    ↓
Patient appointment list updated
    ↓
Doctor appointment list updated
    ↓
Notification generated
```

If a patient sends a message:

```text
Patient
    ↓
Message
    ↓
Doctor conversation updated
    ↓
Unread notification/count updated
```

If a patient shares a report:

```text
Patient
    ↓
Report
    ↓
AI summary
    ↓
Share with doctor
    ↓
Doctor sees shared report
```

If a hospital creates a blood request:

```text
Hospital
    ↓
Blood request post
    ↓
Hospital followers identified
    ↓
Notifications generated
    ↓
Donors see notification
    ↓
Donor opens request
    ↓
"I CAN HELP"
    ↓
Hospital receives donor response
```

All these state changes must work inside the prototype.

# 18. BLOOD REQUEST NOTIFICATION ENGINE

This is a core feature.

Whenever a hospital publishes a new active blood-request post:

```text
Hospital
    ↓
Creates Blood Request
    ↓
System identifies followers
    ↓
System creates notifications
    ↓
Followers receive notifications
```

For example:

```text
XYZ Hospital ✓

URGENT B+ blood request

2 units required

[ I CAN HELP ]
```

Notification:

```text
🩸 Blood Request

XYZ Hospital needs B+ blood.
2 units are required.

Tap to view the request.
```

For the prototype, **every active follower must receive a notification**.

Optionally, the notification system can prioritize:

```text
1. Matching blood group
2. Nearby followers
3. Other followers
```

But the core requirement is that the hospital's followers are notified.

```text
Extraction
Summarization
Translation
Organization
Communication
```
